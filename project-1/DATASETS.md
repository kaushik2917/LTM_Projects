# Dataset-backed FAPT-Guard research

Current temporal dataset: **v2.0.0**, 1,000 reproducible synthetic scenarios with disjoint training, probability calibration, conformal calibration and test groups. See [Temporal pipeline v2](docs/temporal-pipeline-v2.md). Original v1.0.1 files remain unchanged.

The running application is `backend/app` (FastAPI) and `frontend` (Next.js).
The older `fapt_guard/src` contains preliminary schemas and expert knowledge;
it is not a complete TC-FAPN implementation. Its existing `.venv` was used to
train and test the new dataset services.

## Included data and results

### Synthetic temporal dataset v1.0.1 (October 3, 2026)

The frozen model now has a separate [uncertainty/evaluation run](docs/prediction-uncertainty-evaluation.md), generated with `python -m app.datasets evaluate-temporal`. It verifies scenario and full-sequence separation, executes all test prefixes, stores entropy summaries and ECE/Brier diagnostics, and records conformal eligibility without inventing coverage.

`data/custom/synthetic_temporal/` contains the verified supplied archive contents: 600 scenarios, 4,175 events and 3,575 next-technique samples. The supplied scenario splits are preserved: 480/60/60 scenarios and 2,855/360/360 samples. The manifest version is 1.0.1 despite the ZIP filename ending in v1.0.

Use the existing dataset CLI from `backend/`: `python -m app.datasets import-temporal <zip-path>` followed by `python -m app.datasets train-temporal`. Training normalizes T1077 to T1021.002 and T1562.001 to T1685 using pinned ATT&CK replacement relationships, preserving source bytes. The selected transition-frequency model has test accuracy 0.35, Macro-F1 0.116613 and weighted F1 0.286661. Training and validation do not use test targets. Research displays both candidate models, the confusion matrix, provenance and limitations.

**SYNTHETIC DATASET — NOT REAL-WORLD VALIDATION.** The source includes legacy labels; derived training labels are normalized to active IDs. Unseen validation/test target classes remain in evaluation. See the [research validation report](docs/synthetic-temporal-validation.md) before interpreting these results.

| Source | Rows | Implemented use |
| --- | ---: | --- |
| Dataset 10 | 7,700 | CDFU utility regression; ACES action-conditioned survival and response-outcome regression; derived ELC/ERS; weighted response comparison |
| Dataset 11 | 5,000 | AFIP behavior classifier; advisory preservation target/action metadata |
| Dataset 12 | 8,000 | Evidence-trust and graph-integrity regression; poisoning classification from supplied indicators |
| Dataset 13 | 1,890 | Evaluation-only fixture stress test; excluded from fitting |

Dataset copies live in `data/custom/`. SHA-256 hashes, roles, columns and counts
are recorded in `data/manifest.json`. Trained artifacts and held-out scores are
in `data/models/`; the four custom CSVs and model metadata are included in Git. Model binaries
are regenerated by training; external ATT&CK/OpTC files are downloaded separately.

Dataset 11 declares `synthetic_rule_based` labels; every dataset 13 row declares
synthetic ground truth. Datasets 10 and 12 are user-supplied research tables,
not raw OpTC events. Their generation provenance was not supplied. No custom
row is silently converted into an authentic host observation.

The local workflow stores full evidence snapshots and their SHA-256 hashes in
`data/workflow.sqlite3`. Assessment and simulation records link the chosen action
to its saved model estimates and preservation record. This is a simulation-only
provider: it does not capture live-host memory, contain a host, or claim a
calibrated safety certificate. The fixture hashes have a limited legacy scope;
the preserved snapshot hash covers the complete captured snapshot.

Workflow API routes are under `/api/workflow/{incident_id}/`: GET `graph` and
`report`; POST `preserve`, `assessment`, and `simulate`.

```powershell

..\fapt_guard\.venv\Scripts\python.exe -m app.datasets evaluate
..\fapt_guard\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Training uses seed 42 and 80/20 grouped splits: incident ID for datasets 10/12,
sequence ID for dataset 11. There is no group overlap. Outcome scores, optimal
actions and future-stage labels are excluded from model inputs. Dataset 13 is
never opened by the training function. Restart the API after retraining to
clear model caches.

Observed held-out results:

| Model | Result |
| --- | --- |
| CDFU | MAE 0.02255 |
| ACES and response outcomes | MAE 0.01281 |
| AFIP | Accuracy 0.613; macro-F1 0.0881 |
| Trust / graph integrity | MAE 0.00488 |
| Poisoning | Accuracy 1.0 on supplied corruption indicators |

The AFIP macro-F1 is poor: do not use its predictions to trigger automatic
preservation or response. The poisoning result is not a raw-event detection
claim: inputs include `fake_node`, `fake_edge`, spoofing and integrity flags
that must be supplied by an upstream detector. Trust prediction is a tabular
baseline, not completed dynamic graph trust propagation.

## Response semantics

CDFU estimates utility for 11 artifact classes. ACES estimates survival per
class for each of 11 actions. The service computes:

```
ELC = sum(utility_i * (1 - survival_i))
ERS = 1 - ELC / sum(utility_i)
objective = .40 * residual_risk + .30 * (1 - ERS)
          + .15 * business_impact + .10 * response_cost
          + .05 * evidence_opportunity_cost
```

This reports both raw utility-weighted ELC and normalized loss. The objective
weights are explicit research defaults, not learned values. Comparing
action-conditioned predictions supports an initial JCFE/U-EPPC workflow;
it does not establish causal effects, a full digital twin, calibrated safety,
or validated uncertainty-aware optimization. All outputs are recommendations;
no host actions or invasive evidence collection execute.

The requested ATT&CK JSON downloaded successfully. The OpTC ground-truth PDF
and its acquisition hash are in `data/optc/`. Google Drive allowed folder
listing, but the selected `AIA-201-225.ecar-last.json.gz` returned an HTML
access/quota page after download confirmation. No raw OpTC events were
downloaded or substituted. The full collection is roughly 1 TB compressed;
start with a selected file rather than downloading the entire folder tree.

Public-data helper commands (from `backend/`):

```powershell
python -m app.fetch_public_data mitre
python -m app.fetch_public_data optc-ground-truth
python -m app.fetch_public_data optc-list --id 1n3kkS3KR31KUegn42yk3-e6JkZvf0Caa
python -m app.fetch_public_data optc-file --id FILE_ID --name sample.json.gz --max-mb 250
python -m app.datasets import-optc ..\data\optc\sample.json.gz --limit 100000
```

The importer streams lines, reports rejected records, retains exact raw bytes,
and deduplicates byte-identical records by SHA-256. Conflicting versions with
the same source event ID remain separate observations. It retains UUIDs
rather than collapsing entities by executable name. Missing zero UUIDs get
distinct graph nodes. Timestamps require a timezone or epoch milliseconds.
Host/day groups are exploratory windows, not confirmed attack incidents.

Use `/api/research/optc/evidence?limit=100` to browse imported records, and
`/api/research/optc/graph?incident=OPTC:HOST:YYYY-MM-DD` to build a bounded
temporal multigraph. Rule mappings are hypotheses, not attack ground truth.
The STIX catalog supplies vocabulary; it does not itself classify telemetry.

## APIs

`GET /api/research/datasets`, `/examples`, `/benchmark`,
`/techniques/{technique_id}`, `/optc/evidence`, `/optc/graph`.

`POST /api/research/responses`, `/anti-forensic`, `/trust` accept validated
feature inputs. `/examples` supplies reproducible request bodies. Numeric
